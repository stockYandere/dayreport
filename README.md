## 3.0.0

## 바뀐 점

- 앱 이름 `dayreport`. 패키지(`com.dongwon.sleeptimeline`)와 서명 키는 2.0.2와 같아서 덮어 설치하면 수면 기록이 그대로 남는다.
- 하단 탭 5개: **하루 / 시간대 / 앱별 / 수면 / 할 일**. 앱을 열면 `하루`가 먼저 보인다.
- **하루**: 날짜별로 0–24시 흐름(수면 · 앱 사용 · 한 일 표시), 수면/앱 사용/한 일 요약, 많이 쓴 앱 3개, 그날 한 일 목록. 요약을 누르면 해당 화면으로 이동하고, 앱 사용은 그 날짜의 시간대 그래프를 연다. 좌우 스와이프로 날짜 이동. 앱 사용은 시스템 기록 때문에 최근 7일만 조회된다. 수면은 기상일 기준.
- **할 일**: 목록(추가 · O 완료 · X 안 함 · 눌러서 수정)과 기록(최근 30일, 수정 · 할 일로 되돌리기 · 삭제). `한 일 바로 기록`은 할 일을 거치지 않고 시간과 함께 남긴다.
- **바탕화면 위젯 `할 일`**: 기존 위젯과 같은 모양(헤더 + , O / X, 오늘 완료 N개, 기록 보기). +는 작은 입력창, O/X는 바로 처리, `기록 보기`는 앱의 할 일 기록, 제목을 누르면 할 일 목록. 자정이 지나면 오늘 완료 수를 다시 센다. 기존에 쓰던 다른 할 일 위젯의 데이터는 옮겨지지 않는다.
- **시간대 막대**: 막대 하나 = 1시간, 위쪽이 정각(0분) 아래쪽이 60분. 앱별 색 구간을 실제로 쓴 분 위치에 그리고 칸이 충분하면 `14–32`(14분부터 32분까지)를 적는다. 더 크면 앱 이름도 함께 적는다. 왼쪽에 0/20/40/60분 눈금. 같은 앱을 1분 안에 다시 열면 한 구간으로 합친다. 표시 대상은 기존처럼 그 시간 10분 이상 앱(모두 미만이면 상위 3개).
- 막대를 누르면 `14:03–14:21 유튜브 18분`처럼 그 시간에 쓴 구간을 시간 순서로 보여 준다. 숨겨진 짧은 사용은 `그 밖의 짧은 사용 N개 앱 · M분`으로 합쳐 표시.
- 앱별 화면에서 앱 줄을 누르면 그날 그 앱을 쓴 모든 구간(시작–끝, 길이)을 보여 준다.
- 백업 파일에 할 일/한 일도 함께 저장하고 복원한다(같은 제목·생성 시각은 건너뜀). 2.x 백업도 그대로 복원된다.

## 저장

- 할 일: 새 `tasks.db` (`open` / `done` 완료 / `skipped` 안 함, 처리 시각). 기간 제한 없이 보관.

# 사용 흐름 2.0.2

- 미사용 줄은 확인창 대신 후보 목록을 먼저 연다. 선택 날짜와 겹치는 사용 세션 사이 미사용 구간을 모아서 최근 순으로 표시하고 후보별 수면 확정/기록 수정 버튼을 둔다. 완료된 두 앱 사용 끝점을 기준으로 계산, 겹치거나 이어지는 사용은 병합, 자정을 넘는 구간은 자르지 않는다. 관측 범위 앞뒤에 수면 구간을 만들어 넣지 않는다. 5시간 이상, 기존 저장 가능 범위인 24시간 이하의 완결 구간만 제시한다.
- 미확정 자동 수집은 화면 꺼짐→다시 사용이 5시간 이상일 때만 실행한다. 기존 5시간 미만 후보는 조회에서도 숨긴다. 확정된 짧은 수면·낮잠은 유지한다. 이전 최소 시간 설정은 더 이상 사용하지 않는다.
- 내 기록/미확정은 큰 카드 없이 한 줄 44px로 최근 기상일/시각 순으로 위에서부터 쌓는다. 기록이 적어도 행이 늘어나지 않는다. 날짜(기상일), 시간 범위, 길이, 수정/확정 버튼을 같은 줄에 배치. 미확정에는 바로 삭제 버튼. 목록만 길면 화면 높이로 계산한 숫자 페이지를 제공한다.
- 삭제 후보는 dismissed 상태를 보관해 자동 수집 후 재등장하지 않게 하고, 네이티브 후보 보기에서도 양방향 80% 이상 일치하는 삭제 구간을 제외한다.
- 상단은 내용 높이에 맞추고 위/아래 패딩을 준다. hidden 설명문을 CSS가 다시 보이게 하던 문제를 수정해 패턴/기록 버튼과 목록 필터의 겹침을 해결한다.
- 하단은 네이티브/웹 모두 아이콘 없는 3개 글자 탭. 동일한 56dp/CSS px 높이, 좌우 12px 여백, 간격 5px, 모서리 9px, 테두리 색, 선택 색을 적용. 탭마다 얇은 박스 선으로 좌우 구분.
- 5개 화면 크기 30개 UI 상태 검사, 5시간 경계/자정/여러 후보/정렬 7개 Java 검사, 고정 한 줄 높이와 상단 간격/삭제/후보 선택·복귀 검증. 원래 사용시간 집계 8개와 기존 수면 로직 검사도 통과. APK 컴파일·서명 검사. 실제 Android 설치/네이티브 화면은 미검증.
- 기존 2.0.0/2.0.1과 패키지·서명 키·DB 스키마 동일, 설치 업데이트 시 기록 유지. 원본 v1.7 서명 제약은 이전 설명과 같다.

# 사용 흐름 2.0.1 통합판

## 현재 구성

기존 Device Timeline v1.7 APK에서 Models, UsageRepository, DashboardView를 복원해 기존 Canvas 화면과 시간 그래프를 유지했다. 디컴파일에 실패한 지역 변수·이벤트 반복 분기는 같은 동작으로 다시 작성했다. 첫 화면은 기존 시간대 그래프다. 날짜 선택, 첫 사용/마지막/실사용, 64dp 시간 간격과 38dp 굵은 막대, 색 분할, 그래프 내부 좌우 이동, 앱 아이콘/앱별 목록을 유지한다. 앱 목록은 사용자 최신 기준인 10분 이상 및 모두 미만 시 Top3를 적용했다.

원래 `미사용` 줄 오른쪽에 작은 `수면 확정` 버튼을 추가한다. 구간은 기존과 동일한 이전 날짜 마지막 앱 사용 → 선택 날짜 첫 사용이다. 줄/버튼을 누르면 원래 화면 위에 확인창을 띄우고 정확한 날짜와 시간을 채운다. 실제 취침·기상으로 수정해 저장하며 저장/취소 후 기존 화면으로 복귀한다. 겹치는 확정 기록이 있으면 `기록 수정`으로 표시하고 기존 기록을 연다. 최소 후보 기준을 통과하지 못한 구간도 사용자가 직접 확인해서 기록할 수 있으나 24시간 초과/미래/역순/겹침은 저장하지 않는다.

하단 탭은 시간대 / 모든 앱 / 수면 기록. 수면 기록 탭 안에 작은 1 패턴 / 2 기록 버튼으로 기존 수면 그래프와 저장 목록을 조회한다. 새 수면 앱 첫 화면으로 바꾸지 않는다. 기존 아이콘과 `사용 흐름` 이름을 복원한다. 부모 호스트에 인셋을 적용하고 원래 Canvas에서는 중복 적용하지 않는다.

서명 키는 2.0.0과 같고 패키지도 `com.dongwon.sleeptimeline`로 유지해 2.0.0 설치본에 업데이트 설치할 수 있다. 원본 v1.7 `com.dongwon.devicetimeline`의 서명 개인 키는 원본 아카이브에 없으므로 v1.7 설치본 자체를 덮지는 않는다. signing.jks를 이후 업데이트용으로 보관한다.

2.0.1 검증: 원본 복원 Canvas/브리지 Java 컴파일 및 dex 생성, APK 서명 검사. Web 수면 화면 5개 크기의 25개 상태에서 넘침·버튼 잘림·JS 오류 검사. 원래 그래프→미사용 확인 시간 전달, 저장 시 복귀, 같은 구간 기록 수정, 하단 네이티브 시간대/앱 목록 호출, 메모 입력과 시간 검증/삭제 확인 테스트. 실제 Android 기기 설치와 원본 Canvas 런타임 화면은 미검증이다. 이전 2.0.0 Playwright 결과는 원본 Canvas 검증으로 간주하지 않는다.

# 수면 타임라인 2.0.0

Device Timeline v1.7의 수면 중심 후속 앱. 원본 자료에는 APK만 있어 소스를 새로 구현했다. 원본 APK 패키지는 `com.dongwon.devicetimeline`, 이 앱은 `com.dongwon.sleeptimeline`. 별도로 설치되며 기존 앱을 제거할 필요가 없다. 이 프로젝트의 signing.jks를 유지해야 이후 같은 앱의 업데이트 설치가 가능하다. 키는 이 프로젝트 전용 로컬 서명 키이고 build.sh에 암호가 있다.

## 사용 흐름

- 첫 화면은 최근 7개 날짜를 24시간 축에 나란히 표시. 자정 경계를 나눠 그린다. 좌우 스와이프/화살표로 주간 이동, 날짜 누르면 구간 확인.
- 수면/낮잠은 확정한 기록, 점선은 미확정 추정. 평균은 확정 기록의 기상 날짜를 기준으로 기록이 있는 날에 대해서만 계산한다. 하루 총 수면은 낮잠 포함, 취침·기상 평균은 하루 가장 긴 `수면` 구간으로 계산. 시각은 원형 평균을 사용하며 분산이 크면 `다양함`으로 표시.
- 미확정 구간을 수정·확정하거나 `수면 아님` 처리. 직접 기록, 종류, 선택 메모. 시작·끝은 날짜와 시각을 함께 입력. 잠 시작/기상 기록은 재실행해도 시작 시각을 보관한다.
- 기록은 최신순, 화면 높이에 맞는 숫자 페이지. 삭제는 확인창 사용. 메모는 별도 작은 입력창에서 작성하여 키보드로 큰 편집창이 가려지지 않는다.
- 사용시간은 시간별 1시간 막대, 60분 대비 높이, 주 사용 앱 색, 현재 시간 강조, 터치 시 앱 내역. 앱별은 10분 이상, 모두 10분 미만이면 상위 3개.
- 기본 다크, 하단 3탭, 앱 전체 스크롤 없음, 애니메이션 없음, 작은 보조 버튼, 실제 systemBars/displayCutout/IME 인셋 적용.

## 수집·보관

Android UsageStatsManager 사용정보 접근 권한을 사용자 설정에서 승인한다. 인터넷/접근성/다른 앱 위 표시 권한을 요구하지 않는다.

SCREEN_NON_INTERACTIVE(16) → KEYGUARD_HIDDEN(18) 또는 ACTIVITY_RESUMED(1) 두 끝점이 확인된 미사용 구간을 후보로 저장한다. 단순 SCREEN_INTERACTIVE(15)는 잠금 화면 알림일 수 있어 종료 근거로 사용하지 않는다. DEVICE_SHUTDOWN(26), 미완료, 최소 기준 미만, 18시간 초과는 후보에서 제외. 기본 최소 90분, 60/90/120분 선택. 낮·밤 필터 없음. 이는 실제 수면 측정이 아니며 사용자가 수면을 확정한다. 매우 짧은 야간 각성 후 구간을 자동 병합하지 않는다.

약 6시간 주기의 persisted JobScheduler와 앱 새로고침 시 최근 7일 시스템 이벤트를 읽는다. 절전·강제 종료로 실행이 지연될 수 있다. 빈 데이터/끝점 미확인은 수면으로 만들지 않는다. 시스템 원시 이벤트를 장기 보관하지 않는다.

SQLite `sleep.db`에 확정 기록은 자동 만료 없이 저장, 미확정·제외 기록은 30일 보관. 시간 겹침 방지, 동일 후보 중복 생성 방지, 후보 제외 및 확정 후 재등장 방지. 개별 기록의 시간대 ID를 저장하며 화면은 현재 기기 시간대로 표시한다.

백업은 SAF ACTION_CREATE_DOCUMENT JSON. 확정 기록만 내보낸다. 복원은 ACTION_OPEN_DOCUMENT 후 확인, 크기 2MiB / 10,000기록 제한. 스키마·시각·종류·메모 검사, 정확히 같은 확정 기록은 건너뜀, 중복 시간은 전체 트랜잭션 롤백. 기존 기록을 덮어쓰지 않는다. 앱 제거 시 로컬 기록이 사라질 수 있으므로 사용자 백업을 이용한다.
